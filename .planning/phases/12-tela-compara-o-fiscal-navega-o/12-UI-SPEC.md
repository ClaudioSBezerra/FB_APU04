## Spacing Scale

Declared values (must be multiples of 4), matching project-wide Tailwind defaults already in use:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Table cell vertical padding (`py-1`), icon gaps |
| sm | 8px | Table cell horizontal padding (`px-2`), compact filter row gaps |
| md | 16px | Card internal padding, gap between filter controls (`gap-3`/`gap-4`) |
| lg | 24px | Vertical rhythm between major page blocks (`space-y-6`) |
| xl | 32px | Reserved, not required for this screen |

Exceptions:
- **Dense table density is intentional and required**, not a shortcut: table cells use `py-1 px-2` (4px/8px) with `text-[11px]` content, exactly matching `ConciliacaoBridgeXML.tsx` and `ComparativoEFDvsXML.tsx`. This screen will likely show 6 taxes × 3 values (esperado/calculado/diferença) = 18 numeric columns per row; standard `md` padding would make the table unusably wide. Do not "fix" this to a looser density — it is the established convention for this exact screen family.
- Filter control wrapper (Switch + Label for "só divergentes") uses `flex items-center gap-2 rounded-md border px-3 py-1` (4px vertical padding — tightened from the `py-1.5` seen in `IcmsFronteira.tsx` because 6px is not on the declared 4/8/16/24/32 spacing scale; matches the dense table density already used elsewhere in this spec).

## Typography

Sizes and weights pre-populated from actual usage in `ConciliacaoBridgeXML.tsx` and `ComparativoEFDvsXML.tsx` (not invented) — reusing exactly what the codebase already does for this screen family.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro/Data (table cells, badges, chart tick labels) | 11px (`text-[11px]`) | 400 regular (values), 600 semibold reserved for the "esperado" column only (see Divergence Visual Rules) | 1.4 |
| Caption (filter labels, footnotes, legends, tooltips triggers) | 12px (`text-xs`) | 400 | 1.4 |
| Body (paragraph copy, dialog body text, card title labels) | 14px (`text-sm`) | 400 regular (paragraphs), 600 semibold (card title labels, e.g. "Total de Itens") | 1.5 |
| Heading/Display (page H1, KPI card big numbers, dialog title) | 20px (`text-xl`) | 600 | 1.2 |

Only 2 weights declared: **400 (regular)** and **600 (semibold)**. Do not introduce `font-medium` (500) in this new screen even though one legacy screen (`ConciliacaoBridgeXML.tsx` supplier name cell) uses it — that is a pre-existing outlier, not a pattern to repeat.

## Color

Resolved from `frontend/src/index.css` CSS variables (light mode — this project has no dark-mode toggle wired to any page yet, build for light mode only).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(210 20% 98%)` ≈ `#F8FAFC` (`--background`) | Page background |
| Secondary (30%) | `hsl(0 0% 100%)` = `#FFFFFF` (`--card` / `--sidebar-background`) | Card surfaces, table container background, sidebar |
| Accent (10%) | `hsl(217 91% 60%)` ≈ `#3B82F6` (`--primary`) | Reserved strictly for: (1) primary button background ("Exportar Excel" / "Atualizar" buttons), (2) active tab underline/indicator in the module sub-nav, (3) links and the "Ver detalhes" action icon, (4) focus rings on inputs/buttons. Never used for divergence status — status colors are semantic, not accent. |
| Destructive (semantic, not the 10% accent) | Tailwind `red-50`/`red-700`/`red-200` (soft palette), NOT the raw `--destructive` CSS var (`hsl(0 84% 60%)`, too saturated for row/cell highlighting) | Divergent cell badges, divergent row tint — exact classes: `bg-red-50 text-red-700 border-red-200` for badges, `bg-red-50 hover:bg-red-100` for row background, matching `ConciliacaoBridgeXML.tsx` verbatim |

Additional semantic colors required by this screen (not primary/secondary/accent, used only for status, same soft-Tailwind-palette convention as above):

| Status | Classes | Meaning |
|--------|---------|---------|
| Sem divergência (OK) | `bg-gray-50 text-muted-foreground` badge, or plain muted text, no badge at all if value truly equals expected | Value matches, non-alarming, low visual weight |
| Divergente (por imposto) | `bg-red-50 text-red-700 border-red-200` | `abs(diferença) != 0`, no rounding tolerance (fiscal validator — 1 cent matters, per validated reference rule) |
| Não calculado (status != 'ok') | `bg-slate-100 text-slate-600 border-slate-200` (neutral gray, deliberately NOT red and NOT amber) | Row-level state when `fiscal_execution_items.status` is `error`, `sem_grupo_fiscal`, or `pending` — must never be rendered as "divergente" (false positive) per the validated reference rule from FB_TESTESFC |

Accent reserved for: primary action buttons, active nav/tab indicator, interactive links/icons, focus rings — **never** for divergence/status indication.

## Screen Layout (Comparação Fiscal)

Single-page screen, no tabs needed inside it (unlike `ConciliacaoBridgeXML.tsx`'s 2-tab layout) — TPF-06/07/08 describe one list view, not multiple report modes.

1. **Header**: H1 "Comparação Fiscal" + `HelpCircle` tooltip explaining esperado(XML)-vs-calculado(pacote) comparison, same affordance as `ConciliacaoBridgeXML.tsx` header. Subtitle line below.
2. **Summary cards row** (4 cards, `grid grid-cols-1 sm:grid-cols-4 gap-4`, same `Card`/`CardHeader`/`CardTitle`/`CardContent` pattern as reference screens):
   - "Total de Itens" — count of rows in `fiscal_execution_items` for the active filters
   - "Sem Divergência" — count where all 6 taxes match exactly
   - "Divergentes" — count with at least 1 tax mismatched
   - "Não Calculados" — count with `status != 'ok'`
3. **Per-tax divergence breakdown** (secondary summary, satisfies success criterion 5 "resumo agregado ... por tipo de imposto"): a compact row of 6 stat chips below the 4 KPI cards, one per tax (ICMS, ICMS-ST, PIS, COFINS, IBS, CBS), each showing `{count} ({pct}%)` divergent, styled as small `Badge` with the red-50/red-700 divergence palette when count > 0, gray-50/muted when count = 0. Example: `ICMS: 12 (8.4%)`.
4. **Filter row**: "Só divergentes" Switch+Label (bordered box pattern from `IcmsFronteira.tsx`), plus any existing period/NF-e filters the planner decides are needed (not specified by success criteria — Claude's discretion, default to no extra filter beyond the divergence toggle for v1).
5. **Comparison table**: dense table (`text-[11px]`, `py-1 px-2` cells), one row per `fiscal_execution_items` record joined to its `nfe_saidas_itens`. Columns:
   - Item identification: NF-e/chave (truncated + mono font), produto, CFOP
   - For each of ICMS, ICMS-ST, PIS, COFINS, IBS, CBS: 3 sub-columns — Esperado (XML, 600 weight), Calculado (pacote, 400 weight muted), Diferença (Badge, red if `!= 0`, gray if `== 0`)
   - Status column: "OK" / "Divergente" / "Não calculado" badge (row-level rollup, using the 3-state palette from Color section)
   - Row-level tint: `bg-red-50 hover:bg-red-100` when any tax is divergent (matches `ConciliacaoBridgeXML.tsx` `delta_total > 0.01` row-tint pattern), `bg-slate-50` when não calculado, no tint when OK
   - Trailing "Ver detalhes" icon button opening the Dialog
6. **Detail Dialog** (per validated FB_TESTESFC reference): 3 sections —
   - "Identificação": chave NF-e, número item, produto, NCM, CFOP
   - "Comparação": same esperado/calculado/diferença breakdown as the table row, full precision, all 6 taxes
   - "Só calculado" (fields with NO `nfe_saidas_itens` counterpart — DIFAL %, `valor_icms_partilha_destino`, `valor_icms_pobreza`/FCP, plus any additional `full_result` JSONB fields the planner decides to surface): must carry a visible note "Campos abaixo só existem no retorno do pacote fiscal — sem valor esperado correspondente no XML" so the user never mistakes "no expected value" for "zero/divergence"
7. **Export**: "Exportar Excel" + "Exportar CSV" buttons below the table, `outline` button variant, `FileSpreadsheet`/`Download` icons — same placement/style as `ConciliacaoBridgeXML.tsx`
8. **Threshold legend footnote**: "(divergência = qualquer diferença ≠ R$ 0,00 — sem tolerância de arredondamento)" — deliberately different wording from the R$0,01 threshold used in `ConciliacaoBridgeXML.tsx`, because this is a fiscal *package validator*, not an ERP-vs-XML reconciliation; the reference implementation's rule (zero tolerance) must be visually communicated as intentionally stricter, not a bug/inconsistency with the sibling screen.

## Divergence Visual Rules (binding, from validated FB_TESTESFC reference)

1. Divergence rule is **`abs(esperado - calculado) != 0`** for every base/valor pair (ICMS base+valor, ICMS-ST base+valor, PIS base+valor, COFINS base+valor, IBS UF+MUN, CBS) — **no rounding tolerance**. Do not reuse the `> 0.01` threshold from `ConciliacaoBridgeXML.tsx`; that threshold is specific to ERP-vs-XML reconciliation noise and does not apply to a package-output validator.
2. `fiscal_execution_items.status != 'ok'` (i.e. `error`, `sem_grupo_fiscal`, or `pending`) → row renders as **"Não calculado"**, never "Divergente", regardless of what any typed comparison column would otherwise compute (values may be NULL/0 in this state — do not evaluate divergence at all for these rows).
3. IBS/CBS caveat: expected-side values (`v_ibs`/`v_cbs` in `nfe_saidas_itens`) are frequently NULL/0 today because the XML parser does not consistently populate them (confirmed in `.planning/.continue-here.md` §"decisao_chave_reuso_de_dados"). This means IBS/CBS will show as "divergent" very often even when the pacote fiscal is working correctly. The UI must not hide or suppress this — show it plainly per rule #1 — but must carry the mandatory tooltip caveat (see Copywriting Contract) so users don't file false bug reports against the pacote fiscal for a known data-source gap.
